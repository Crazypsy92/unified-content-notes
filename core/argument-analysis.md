## 通用观点分析：基础模块

**模块类型：基础模块（无父模块）。** 适用于情感以外的观点口播、评论文章、读书感悟、社会观察、职场观点、哲学讨论、长帖和其他以论证为主的材料。

情感关系主题应在本模块基础上加载 modules/relationship-analysis.md；专项模块只增加领域分析，不复制本模块的通用写作规则。

## 默认成稿结构

1. **原始标题**：逐字保留。
2. **来源**：在标题下标注一次；没有可靠出处则不猜。
3. **观点总览表**：长篇、多论点或多案例材料通常使用紧凑表格，建议列为“核心论点 / 原文依据或案例 / 推理关系 / 结论或适用边界”。短材料、单一观点或不适合表格的内容可以省略。
4. **正文**：按原材料的论证顺序写成自然、可独立阅读的文章；用少量真实逻辑小标题，不机械套重复模板。
5. **用户感悟**：如素材包含用户自己的评论、感想或复盘，放在末尾并与来源观点区分；没有则不新增。
6. **观点边界**：只有出现明显绝对化、证据不足、因果跳跃或用户要求核验时，才增加必要说明。

## 论点与证据

- 每行对应一个独立论点，或一组确实紧密相关的论点。
- 识别主张、前提、理由、证据、推理关系、反例和适用边界；不要把作者结论自动当作事实。
- 表格只负责导航，不能替代正文论证；正文也不逐行复述表格。
- 不同案例即使结论相似，只要提供了不同证据，就不能合并成一个模糊例子。

## 案例在正文中展开

核心案例保留理解论证所需的事实链：

- 必要背景、人物关系或场景；
- 事情起因和关键行为；
- 来源提供的关键原话、对话或数字；
- 对方回应、可观察结果或后续变化；
- 案例支撑什么观点，以及不能证明什么。

案例之后紧接分析，不扩写成小说。不得补造环境、表情、动作、心理独白、背景、台词或结局。辅助案例可以比核心案例短，但不能删掉它独有的证据。

## 正文口吻

- 直接写观点、事实和推理，避免反复使用“作者认为 / 原文指出 / 讲者通过例子说明 / 这篇文章讲了”等旁白。
- 保留原材料的人称和表达力度：第一人称经历保留“我”，直接对听众说话可保留“你”，客观观点直接陈述。
- 保留有辨识度的反问、比喻、对照和反例，不额外添加煽情内容或鸡汤结尾。
- 不把复杂观点缩成观点清单；正文必须保留足够证据，让读者理解结论如何成立。
