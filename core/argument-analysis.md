## 通用观点分析：基础模块（观点分析型）

**模块类型：基础模块（无父模块）。** 适用于情感、职场、社会观察、个人成长、读书观点、评论、长篇口播及其他有“主张—论据—推理”的材料。情感观点类额外加载 [情感观点分析](../modules/relationship-analysis.md)，但仍使用本模块的同一套结构。

**默认交付：每个话题一个原始标题 + 观点表格 + 高保真浓缩正文 +（有原文时）折叠原文。** 这不是“一句观点 + 一点解释”的简短摘要。表格帮助检索，浓缩正文让人读懂完整论证，原文提供可追溯的依据；三者不能互相取代。

## 一、观点分析型的交付契约

对每个独立话题依次输出：

1. **原始标题**：只用一个二级标题（##），逐字保留用户提供的标题。多个话题逐篇排列，不强行合并成一篇综合文章。
2. **来源**：在标题下合并成一处，已知时写平台、创作者；未知时不猜。原文中的重复来源标注可移到此处，不能混入正文。
3. **观点速览**：默认使用紧凑的四列表格，列为“核心论点｜具体案例 / 原文依据｜论据如何支撑观点｜最终落点”。原文是条目清单时可按实际结构改为三列，但仍需表格；没有案例时写清楚“原文未提供案例”，不要凭空制造。
4. **浓缩正文**：必须是多段、可独立阅读的完整文章，保留原材料的叙述视角、关键场景、具体人物行为、对话、数字、比喻、对比、反例、转折与结论。删语气词和重复，不删独立论据。
5. **个人感悟 / 观点辨析**：原文确有用户感悟时单独呈现；材料中有明显性别刻板印象、绝对判断、心理学 / 科学未经核实说法或逻辑跳跃时，用简短辨析说明“原文主张—材料能支持什么—不能推出什么”，不要改写掉原文观点。
6. **原文记录**：用户提供了对应完整原文时，放在折叠块中。保留其全部内容和原顺序，只可重新分段、调整空白、加两个全角缩进和必要的 Markdown 排版；不得删除、补造或改写原话。若只提供标题、片段或不可访问的链接，不能伪造完整原文，省略此块或明确标为“原文片段”。

**标题约束：** 一个话题只有一个 ## 标题；“观点速览 / 浓缩正文 / 个人感悟 / 观点辨析 / 原文记录”是标签或 Callout 标题，不使用 ###、#### 再次分节。用户主动要求另一种层级时从用户要求。

**Obsidian 默认样式及准确语法**统一见 [Obsidian 观点分析排版](../references/obsidian-argument-layout.md)。该参考文件只负责展示样式，不在情感模块重复。

## 二、论点—论据—论证

- **论点**：材料真正提出的独立主张，不能只是“爱情很重要”一类空泛概念。
- **论据**：给出可识别的事例 / 对话 / 比喻 / 数据 / 观察；材料只有个人判断时明确是“讲者观点”而不是证据。
- **论证**：写出具体依据怎样支持主张，有哪些缺少的前提、反例或适用条件；“因为有案例，所以观点正确”不是有效推理。
- **最终落点**：主张可支持的结论或行动判断，不将个案绝对化。
- 表格每行对应一个独立逻辑单元；不能把一个大案例塞满单元格，更不能用表格取代正文的完整事实链。
- 单篇材料中的不同案例即使结论相似，只要论据不同，都要在表格可识别，并在正文适当展开。

## 三、高保真浓缩正文：必须看得见例子

先在内部建立观点与原文证据映射，再撰写正文。对每个**核心案例**至少保留：

1. 背景与人物 / 情境；
2. 事情怎么发生，双方或相关人员实际做了什么；
3. 原文提供的关键对话、数字、对照或形象比喻；
4. 后续回应、结果或未交代的部分；
5. 该案例如何支撑对应论点，以及它不能证明什么（必要时）。

浓缩正文不能把“因为项目加班，女友抱怨未回复”取代“临时加班、女友询问归期、深夜才回复、两人的具体解释与分歧”的原始案例。原文没有结局就不要补造。

- 去掉重复口播和空泛连接句，不设固定压缩比例；**压缩的是冗余，不是证据**。
- 正文延续原文的“我 / 你”或客观视角，避免反复使用“作者认为 / 原文指出 / 讲者通过案例说明”等旁白。
- 段落按一个完整意思组织，长段可在真实转折处断开；不能为美观改变逻辑顺序。
- 表格可以精简，正文不能因此变成几条结论；阅读正文应能看懂每个重要观点为什么成立。
- 例子数量多时，可压缩背景雷同的次要例子，但不能合并或遗漏唯一证据、重要反例和关键差异。

## 四、原文折叠与保真

当完整原文由用户提供 / 已在上下文中可合法重用时，折叠原文默认启用：

- 使用 Obsidian 原生折叠 Callout：> [!quote]- 原文记录 · 点击展开。
- 所有内容行以 > 开头；原文自然段使用 > 　　（两个全角空格）作为首行缩进；段落之间有独立的 > 空行。
- 可依据语义与停顿重新分段，不要求维持用户粗略的旧分段；不能随意机械切成每句一段。
- 原文中的标题 / 作者 / 来源等元信息可统一移动到话题标题下的一处，避免原文区域重复展示；**除了重复元信息与允许的 Markdown 排版以外，原文字符不能删改**。
- 原文里的编号列表、已存在的对话和已有表格可以规范排版，保持字词、数字、标点与顺序不变。不能暗中纠错、补全 ASR 错字。
- 未提供原文时不把总结伪装成完整原文；若原文不完整，清楚标注片段边界。
- 对含版权的第三方材料，不得通过搜索拼接未提供的完整原作；遵守 [来源与版权边界](source-boundaries.md)。

## 五、交付验收

内部逐条核对：表格的每个论点有对应正文；正文可看到具体例子；原文完整可展开；一话题一标题；来源无冗余；Callout / Markdown 表格在 Obsidian 可渲染；原文内容除了明确允许的排版与来源元数据调整外逐字一致。若用户只要浓缩、不需要原文，遵循用户指定并省略原文块。
