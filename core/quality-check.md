## 通用质量检查

交付前在内部完成质量检查；除非用户要求，不展示冗长审计过程。

## 四道检查

1. **任务一致性**：是否正确执行总结、讲解或只改格式？是否生成用户没有要求的版本、心理解释或外部信息？
2. **信息覆盖**：独立论点、必要论据、核心案例、关键对话、数字、比喻、反例、转折、限定条件和结局是否保留？
3. **来源忠实**：是否区分事实、创作者观点、被引用者说法、用户感悟、模型推断与外部核验？是否补造心理、台词、动作或因果？
4. **阅读质量**：观点、例子、推理是否看得见；段落长度、标题、表格、Callout、缩进、折叠是否可渲染且不臃肿？

## 观点分析型的专属验收（必须执行）

逐个话题核对：

- [ ] **一个原始 ## 标题**，没有多余 ### / ####、重复章节名或跨话题混合。
- [ ] **来源只出现一次**，平台 / 创作者按已知信息合并；不猜测不明来源。
- [ ] **观点表格存在**，论点、具体依据、论证关系、结论匹配且不是空套话；原文只有条目时按实际内容做三列。
- [ ] **浓缩正文可独立阅读**，不是表格重述，也不是单纯几句结论。
- [ ] **每个核心案例保留事实链**：背景、起因、行动、关键对白 / 数字、回应 / 结果、论证作用；原文没写的细节不补。
- [ ] **用户完整原文可追溯**：原文已提供时默认折叠；逐字记录不删字换义。若用户要求 ASR 校订，折叠区明确标为校订阅读版，原始 ASR 另存备份；素材不足时不伪造。
- [ ] **元信息不重复**：原文折叠里除正文外，不重复显示已移到顶部的来源标签。
- [ ] **Obsidian 可渲染**：Callout 使用合法语法，内部表格每行以 > 开头、列数一致、段落间 > 空行；文章有自然段缩进。
- [ ] **Callout 分隔**：每个 `> [!info]` / `> [!summary]` / `> [!note]` / `> [!quote]-` 等标签之前均有真正空白源码行；孤立 `>` / `> ` 不算分隔；原文折叠正常。
- [ ] **口播段落质量**：每段围绕一个完整意思，长案例按背景、行动、回应和结果拆开；不保留整篇一大段，也不机械地一句一段。
- [ ] **简繁与来源**：整理正文默认简体；原始 ASR 默认不改。明确要求 ASR 校订时，注明“断句校订版”，保留原始 ASR 备份；只有 ASR 文本时说明未核听音频。不得把校订版冒充逐字原文。
- [ ] **静态检查**：运行 `python tests/check_obsidian_callouts.py <file.md>`，条件允许时加 `--simplified` 检查简体阅读版（需 OpenCC），再在 Obsidian 阅读视图抽查。
- [ ] **语义高亮准确**：蓝青色标记核心判断、绿色标记证据 / 案例、橙色标记转折 / 限制 / 风险；高亮完整语义片段，不随机标记孤立名词。ASR 存疑片段不得把猜测出的词高亮成确定事实。
- [ ] **正文与原文都得到处理**：观点分析型总结 / 讲解的 Obsidian 文档在浓缩正文和折叠原文中均按需高亮；默认原文移除 <span> 标签后与未转换来源逐字一致；若用户明确授权简体阅读副本，应改与简体转换参考稿对照，并保留未转换原件。
- [ ] **只改格式保护有效**：未获用户明确授权时，不在 format-only 模式自动增加语义高亮。
- [ ] **来源与解释边界清晰**：个人感悟和必要观点辨析独立呈现，未用解释覆盖原始观点。

## 高保真信息台账

中长材料先在内部建立原文信息单元与输出位置的映射：分论点 → 独有论据 → 案例事实链 → 数字与对比 → 结论边界。验收时逐一对照，避免“字数很多但遗漏关键案例”。信息台账不作为默认交付。

## 根据用户反馈修正

| 用户反馈 | 应对 |
| --- | --- |
| 没有具体例子、正文浓缩太干 | 返回原始素材补回核心案例的完整经过、关键对话和推理，不靠空泛扩写 |
| 只有观点没有论证 | 补齐观点表格的论据与论证链，不能把观点重复三遍 |
| 正文太长、重复 | 删除空泛铺垫、口头禅与重复论证，保留唯一证据 |
| `[!note]` / `[!quote]-` 被显示成纯文本 | 检查上一行是否只是 `>` 而非真正空行；在相邻 Callout 之间插入不带 `>` 的空白物理行，再运行静态检查。 |
| 原始口播繁体、需要简体阅读 | 经用户明确要求后生成简体阅读副本，标明用途并保存未转换备份，不推测性纠错。 |
| Obsidian 排版丑、段落挤 | 优先调整原生 Callout、折叠、段落间距和双全角缩进；需要突出重点时使用语义明确的主题变量高亮，不随机换色 |
| 原文分段太粗 / ASR 口播挤成一大段 | 加载 core/transcript-cleanup.md；按句意、停顿、案例和转折断句分段，高置信度纠错，存疑处标记，保留原始 ASR 备份 |
| 来源重复 | 顶部合并标注一次，原文块去除重复元数据 |
| 第三人称旁白多 | 保留原始人称与直接陈述方式，不让“作者指出 / 原文认为”变成固定口吻 |
| 专项模块抢占基础模板 | 先执行基础布局契约，再叠加领域分析，不另建结构 |

## 其他模式检查

- **叙事**：人物、事件、时间线和结局不串线；未交代保持未交代。
- **知识纪实**：观察、证言、推断、计划和验证事实不混淆。
- **对话**：说话人、轮次准确，建议话术不伪装原话。
- **方法笔记**：步骤、数字、前置条件、输入输出和限制完整。
- **只改格式**：没有总结、润色、校对或重排事件；非排版字符一致。


## 技术知识 / 面试笔记的专属验收

- [ ] 文档采用 `# 文档标题 → ## 章节 → ### 题目`；每道题只有一个题目标题，不存在 `####` 或更低级标题。
- [ ] 右侧大纲只呈现章节和题目；快速索引不再重复制造章节标题，不包含题目内部小标题。
- [ ] 题目内部以普通段落、加粗短语、列表、表格组织；没有为了排版而机械拆分的“一、二、三”小标题。
- [ ] 不为每道题添加 Callout；Callout 数量不超过题目数的 20%，通常每章最多一个，且有明确的信息价值。
- [ ] 深色主题下没有连续的大面积背景色块；无 CSS、HTML、内联颜色或背景样式。
- [ ] 行内公式使用 `$...$`，块级公式使用单独成行的 `$$...$$`；分隔符成对，公式没有落入代码围栏。
- [ ] 比较型知识点优先使用真正的 Markdown 表格；案例和原理使用普通正文，不把全部内容塞进表格。
- [ ] 事实、参数、API 语义和标准等级有来源依据；未核实的数字或说法明确标注，不为填满笔记而补造。
- [ ] 案例来源与验证程度清楚，不把方案推演说成实测。
