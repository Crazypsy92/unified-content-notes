## 内容结构路由

内容模式决定材料如何组织。根据实际结构选择一个主模式；复合材料按段落或信息单元组合多个模式，不要强行给全文贴一个标签。

| 内容结构 | 识别线索 | 总结时的组织方式 | 加载模块 |
| --- | --- | --- | --- |
| **观点 / 论证型** | 主张、理由、证据、类比、反问、反例、结论 | 每话题原始标题 + 默认论点/具体证据/推理表 + 事例完整的浓缩正文 + 有原文时折叠保留 | [argument-analysis.md](argument-analysis.md) |
| **情感关系观点型** | 恋爱、婚姻、沟通、择偶、关系冲突、亲密互动 | 沿用观点分析基础结构，额外分析双方行为、互动和关系边界 | 先加载通用观点分析，再加载 [relationship-analysis.md](../modules/relationship-analysis.md) |
| **故事 / 经历 / 作品型** | 人物、处境、目标、冲突、行动、转折、结果 | 按事件与人物变化组织，保留关键对话和结局 | [narrative-analysis.md](narrative-analysis.md) |
| **知识 / 纪实型** | 事实、记录、访谈、证据、时间线、机制、争议 | 区分观察、记录、陈述、推断和计划；组织证据链 | [knowledge-analysis.md](knowledge-analysis.md) |
| **对话 / 访谈型** | 多轮发言、误会、追问、回应、观点交锋 | 标记说话人和轮次；按需分析表达、需求与回应 | [dialogue-analysis.md](dialogue-analysis.md) |
| **方法 / 教程 / 经验型** | 目标、前提、步骤、参数、操作、排错 | 目标与条件 → 步骤 → 输入输出 → 示例 → 限制 | [method-notes.md](method-notes.md) |
| **短文案 / 金句型** | 独立短句、摘录、标题、语录合集 | 保留原句，按主题轻量归类；短内容不扩写成长文 | 通常无需额外模块 |
| **个人感悟型** | 第一人称体验、犹豫、判断、变化、复盘 | 保留第一人称和真实思考顺序；按论证或经历结构组织 | 根据实际结构选择观点或叙事模块 |
| **图文 / 线程 / 多篇合集** | 多张卡片、连续帖子、分 P、多作者回复 | 保留页面 / 帖子 / 章节顺序及作者边界 | 需要时加载 [平台输入参考](../references/platform-and-source.md) |
| **混合型** | 同时包含观点、案例、对话、方法或个人感悟 | 分段识别局部结构，保留各部分之间真实关系 | 只组合必要模块 |

## 路由细则

- 平台是输入载体，不是内容模式。例如，抖音视频可以是论证、故事、教程或混合型。
- “情感观点分析”是“通用观点分析”的领域专项，不是与通用观点分析并列的另一套排版模板。
- 关系素材若以多轮聊天记录为主体，且用户要求分析双方表达，可同时加载对话模块与情感专项；若只要求排版，则只加载 format-only。
- 小说 / 电影 / 纪录片的二手解说不等于原作品；依据实际提供的材料选择模块。
- 非观点类短材料不强制表格；观点分析型默认包含表格和完整正文，但原文仅是极短金句时可切换短文案模式。一个话题只有一个标题，不机械拆分小标题。
- 用户明确指定内容模式时优先；未指定时根据素材判断，不要为了确认分类而打断任务。
