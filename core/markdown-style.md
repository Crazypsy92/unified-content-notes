## 默认 Markdown 与阅读规范

用户明确指定其他格式时优先；真实性与“只改格式”保护不因美化而放宽。

## 标题与段落

1. 保留原始标题、标点，不擅自改题。
2. 通用内容最高标题为二级 ##。**观点分析型每个话题仅一个 ## 标题**；内部用 Callout 或加粗标签“观点速览、浓缩正文、观点辨析、个人感悟、原文记录”，不得再新增 ### / ####。小说 / 技术等非观点分析型仍可按需使用 ###。
3. 中文自然段首行缩进两个全角空格（　　），包括原文折叠块内的自然段；引用块内先写 Markdown 引用前缀 >，再写缩进。
4. 合理分段：一句话不足以构成独立段落时不要机械断开；超过一个完整论证单元的长段在原文已有句末或明确转折处断开。
5. 来源合并为一处：已知时统一平台与创作者；未知不猜测。不要在内容前、原文开头和末尾分别标注相同来源。

## 简繁处理与原文保真

- 整理正文默认用简体；用户未要求变更原文时，原始转录的繁体字、标点、错别字均应保持来源原貌。
- 用户明确要求原文也转为简体时，提供注明「原文转录 · 简体阅读版」的阅读副本，并备份未转换源文件或完整原文；可做字形转换，但不借机猜改 ASR、人名和事实。
- 简繁转换不是纯排版，不能再宣称转换后文本与未转换原件「逐字一致」；应检查原文备份存在、转换前后非字形信息未丢失。
- **Callout 块与块之间要有真正空白行**。独立的 `>` 仍属上一引用块，不能结束引用，常导致下一张 `[!note]` / `[!quote]-` 显示成文字。

## Obsidian 原生样式

- 用户计划在 Obsidian 阅读观点分析型稿件时，默认使用 Obsidian 原生 Callout，而不是把所有内容裸放在页面上。具体标签、折叠、表格和引用的**唯一语法说明**见 [Obsidian 观点分析排版](../references/obsidian-argument-layout.md)。
- 不需要额外插件、CSS snippets 或 HTML 表格。允许仅为语义高亮使用内联 <span>，颜色通过 Obsidian 主题变量（如 var(--color-cyan)）指定；不使用硬编码色值、自定义 CSS 或随机换色。Callout 本身的颜色由 Obsidian 主题决定。
- 不要把整段长原文默认展开：使用折叠原文，优先展示观点表格和浓缩正文。
- Obsidian Callout 内的 Markdown 表格，**每行需以 > 开头**，表头后要有合法的分隔行，每列的 | 数量一致，块之间留空行。
- Markdown 源码模式会显示标记；实时预览 / 阅读视图可显示渲染效果。

## 内容呈现

- 观点表格通常不超过四列；三列表格只用于来源确实是条目清单或没有论证链的特殊情况。
- 表格写“论点—具体证据—推理—落点”，不塞入整段案例全文；案例在浓缩正文里展开。
- 加粗只标少量关键判断；引用 / 表格 / 标题本身不增加首行缩进。
- 个人感悟、外部核验、讲者说法清晰区分，优先保留用户原有的表达。
- 文件和代码标识符默认英文，中文正文按用户要求；只有文件实际存在才提供下载链接。
- 非 Obsidian 目标（例如 GitHub 纯 Markdown / 邮件正文），改用普通 Markdown 表格与加粗标签，保留相同信息结构，不强制使用 Callout。


## 技术八股 / 技术知识笔记的 Obsidian 规则

技术类笔记适用于嵌入式及相邻工程技术，也适用于其他技术面试知识。它不沿用观点分析型的 Callout 卡片结构。

默认标题层级：

- `# 文档标题`
- `## 技术章节`
- `### 原始题目或知识点`

**每道题 / 每个知识点只保留一个题目标题。** 不使用 `####` 或更低级标题；题目内部用普通段落、加粗短语、列表、表格和必要的代码块组织。快速索引只列章节和题目，不列内部说明标签。

- 普通正文是默认；不按题目机械放置 `[!abstract]`。
- 全篇 Callout 不超过题目数的 20%；只有关键安全风险、跨题结论或必须记住的限制才使用。
- 不连续堆叠背景色块，不使用 CSS、HTML、内联文字颜色或背景样式。
- 重点通过加粗、表格、代码块和自然留白表达。
- Obsidian 公式统一使用 `$...$` 行内和单独成行的 `$$...$$` 块级 MathJax；不使用 `\\(...\\)` / `\\[...\\]` 作为默认定界符。
- 具体排版与公式示例见 [Obsidian 技术笔记排版](../references/obsidian-technical-notes.md)。
