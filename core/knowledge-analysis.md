## 知识、纪录片与事实解释

适用于纪录片、科普、历史调查、访谈、研究介绍、社会事件说明和其他以事实 / 证据 / 机制为主的材料。

## 组织方式

根据材料选择时间线、主题线、机制链或证据链，不强制套固定模板。优先保留：

- 问题背景、关键时间、地点和参与者；
- 观察记录、数据、文件或其他可核实材料；
- 专家 / 受访者陈述及其身份和语境；
- 个人经历、创作者判断、假设、推测和行动计划；
- 不同说法之间的支持、冲突和证据缺口；
- 已确认结果、尚未验证的部分和适用限制。

## 证据层级与表达

不要把以下信息混为一谈：

| 信息类型 | 表达方式 |
| --- | --- |
| 直接观察 / 原始记录 | 说明材料实际记录了什么 |
| 数据 / 文件证据 | 保留口径、时间、单位和条件 |
| 专家或受访者陈述 | 标明是该人士的说法，不自动视为定论 |
| 个人经历 / 评论 | 保留为个体经验或观点 |
| 假设 / 推断 | 明确使用“可能 / 推测 / 尚待验证”等表述 |
| 计划 / 预测 | 不写成已经发生或已经证实 |
| 缺失证据 | 明确指出材料没有提供什么 |

## 讲解时

解释术语、机制、因果链和证据之间的关系。出现逻辑跳跃时指出缺失的前提；相关性不能直接推出因果。不要把讲述者立场当成公认事实，也不要无声加入外部研究。

用户要求外部核验时，再单独开展核验，并把外部来源与原材料区分。


## 技术知识库的专项路由

如果材料是嵌入式、RTOS、MCU、硬件基础、通信协议、存储、控制算法等面试知识点，而不是纪录片或调查材料，加载 [技术知识笔记](technical-knowledge-notes.md)。技术知识笔记以“题目”为基本单元，重点解释概念、原理、对比、工程场景和常见误区；不要机械套用时间线或证据链模板。用户只提供原始题目时，先忠实整理；需要补充、纠错或外部核验时，明确区分原始材料与补充知识。
