## ASR 口播转写清理：校订阅读版与原始备份

**加载条件：** 输入是语音识别（ASR）口播、自动字幕或未经人工校对的转录；用户要求修正错词、断句、分段、改善原文可读性，或观点分析型成稿明显需要先整理口播文本时加载。本模块只处理转录文本，不负责下载视频、提取音频或声称完成听写。

## 一、先判断用户允许改到什么程度

- **只改格式 / format-only：** 仍执行零语义改写。可以按用户允许的范围调整段落、空白和 Markdown；不得自行补标点、纠正 ASR、删口头语或替换词语。
- **明确要求校订口播、修正 ASR、整理原文可读性：** 可以生成“口播转录 · 断句校订版”，允许补充合理标点、重分自然段，并修正高置信度错词。
- **只要求观点总结 / 讲解，未要求修订原文：** 不必默认重写原文。若 ASR 错误已经影响论据理解，先在内部区分可确认与不可确认的内容；确需制作阅读版时，清楚标注其校订性质。

## 二、必须区分两个文本层

1. **原始 ASR 备份：** 用户提供的原始转录，原样保存，不做繁简转换、纠错、删改或重新排序。批量任务中随交付包保留源文件。
2. **校订阅读版：** 为阅读而整理的副本，可增加标点、断句、自然段和少量高置信度纠错。Obsidian 折叠标题使用“口播转录 · 断句校订版”，不能继续标成“逐字原文”或声称与原始 ASR 完全一致。

如果没有视频或音频，必须说明“基于 ASR 文本校订，未核听音频”。不得把上下文推断描述成已经听清或核实。

## 三、纠错分级：先保留，再判断

- **高置信度，可直接校订：** 语境、句法和前后文都支持同一个明显错词，且不会改变论点。例如明显的同音错字、常见词被拆错、口播中可唯一确认的固定表达。
- **中低置信度，必须标记：** 有多个可能答案，或需要依赖视频画面、人物身份、专业背景才能确定。使用“听辨存疑：原转写……”；若有一个较可能的候选词，可写“疑似……，待核音频”，不能静默替换。
- **禁止猜测：** 人名、地名、品牌、数字、金额、日期、单位、专业术语、穿搭风格名称、引用原话及残缺结尾。除非音频、视频画面或用户提供的其他可靠来源能直接确认，否则保留并标记。
- **不得补齐：** 标题说“五点”“三件事”，不代表当前转录一定完整；不能从相似视频、相邻话题或已有摘要拼接缺失条目。
- **不得润色成新文案：** 校订阅读版仍应保留讲者的第一人称、口语语气、观点顺序、重复强调和表达力度。只清理影响理解的转写噪声，不替讲者改观点。

## 四、断句与段落：按语义组织，不按字数切块

1. 先识别完整句意，再补逗号、句号、问号、冒号和引号；不能仅凭固定字数机械加标点。
2. 依据自然停顿、主谓关系、因果、转折、举例、递进和总结划分句子。
3. 一个自然段承载一个完整意思，通常容纳 2–4 句；观点切换、案例开始、案例结果、步骤编号和结论出现时另起段。
4. 长案例按“背景 / 起因 → 行为与对话 → 对方回应 → 结果或结论”拆分；保留事件顺序，不把案例拆成互不相关的碎句。
5. 短口播可以只有一段；若素材只有一句或转录严重残缺，不为了排版而扩写。
6. 不要把几十句口播挤成一个大段，也不要每句话都单独成段。段落应当让读者看出论点、论据、转折和收尾。
7. 口头语、重复词只有在明显是识别噪声或无意义的重复起音时才可轻度清理；承担语气、强调或情绪作用的表达应保留。

## 五、校订版的语义高亮

在用户要求观点分析型 / Obsidian 输出时，校订阅读版也使用语义高亮：

- **蓝青色：** 完整核心论点、关键判断、明确结论。
- **绿色：** 具体案例、人物行为、关键对话、数字和可识别的事实。
- **橙色：** 论证转折、对比、反例、适用限制、风险或明显存疑处。
- 高亮完整句子或有完整意义的分句，不给孤立名词随机换色；同一重点不必反复着色。
- 不确定片段不得用肯定语气高亮成事实。必要时高亮其“存疑 / 待核”边界，而不是高亮猜测出的词语。

## 六、交付前检查

- [ ] 原始 ASR 文件有单独备份，且没有被覆盖。
- [ ] 校订版明确标注“断句校订版 / 阅读版”，没有冒充音频逐字稿。
- [ ] 每条口播按语义分段；没有几十句挤在一个段落，也没有机械地一句一段。
- [ ] 高置信度纠错没有改变原意；中低置信度内容均有存疑标记。
- [ ] 人名、数字、单位、专有名词和缺失结尾没有被猜补。
- [ ] 原文顺序、案例事实链、对话、转折和结论均保留。
- [ ] 移除高亮标签后，可恢复校订阅读版的文字；原始 ASR 仍可从备份追溯。
- [ ] Obsidian Callout 边界、缩进、折叠状态和 span 标签均通过静态检查。
