## 格式与质量门槛

### 统一 Markdown 输出

- 原标题原样保留，最高标题级别为二级。
- 中文自然段首行两个全角空格；段间留一个空行。
- 标题、表格、列表、引用不缩进，以免 Markdown 渲染失效。
- 不使用 HTML、强制空行、整段加粗或装饰符号堆砌视觉效果。
- 表格列数克制，避免超宽表格和把长篇正文塞进单元格。
- 用户自己的个人感悟与来源观点分开；有个人感悟时放在文章末尾。
- 来源在标题下标注一次即可，不在正文反复写来源说明。

### 高保真浓缩：完整性优先于极限压缩

默认不是追求最短，而是把材料整理成可独立阅读的浓缩文章。

允许删除：
- 无意义语气词、口播回环和同义重复；
- 没有新增信息的重复例子；
- 与主题无关的引流、口播插话和无关内容。

不能轻易删除：
- 独立论点及其理由、前提和推理关系；
- 论证所依赖的案例、关键动作和对话；
- 数字、时间、金额、步骤、比较和反例；
- 有辨识度的比喻、转折、情绪变化和结尾感悟；
- 结论的适用条件和限制；
- 用户个人补充及其与来源观点的区别。

没有固定字数、压缩比例或段落数。信息密集、案例较多的材料可以保留较长正文。若压缩后读者无法知道案例具体发生了什么，或无法理解它为什么支撑观点，则属于过度压缩。

### 观点分析型

观点分析型沿用原有高保真架构：

1. 原始标题；
2. 标题下标注一次来源；
3. 紧凑的核心论点 / 原文依据或案例 / 推理关系 / 结论或适用边界表格；
4. 按原材料的思想推进顺序写正文；
5. 有个人感悟时放在文章末尾；
6. 只有确有必要时才添加观点辨析或外部核验。

不要强制增加“文章思想、原始文案整理、正文浓缩、最终落点、金句摘录”等模板小标题。可以使用少量真正有助于理解的逻辑小标题，但不为凑数拆分。表格是导航，不是正文替代品。

### 案例与论据完整性

核心案例必须在正文中出现，并保留理解论证所需的事实链：
- 必要背景和人物关系；
- 起因与关键行为；
- 关键原话或对话（来源提供时）；
- 对方回应和可观察结果；
- 案例支撑的观点及其边界。

多个案例即使结论相似，只要证据细节不同，就不能直接合并成一个泛化例子。辅助案例可适度压缩，但不能抹掉它独有的论据。不得补造心理、动作、环境、台词或结局。

### 叙述视角与自然语言

- 不把整理稿写成第三方视频解析报告。
- 正文避免反复使用“作者认为”“原文指出”“讲者通过例子说明”“这篇文章主要讲了”等旁白。
- 直接陈述观点、事件和推理；来源只在标题下标注一次。
- 保留来源原本的人称和表达视角：第一人称经历保留“我”，直接对听众说话可保留“你”，故事按人物叙述，一般观点直接陈述。
- 不要机械地把所有内容改成第一人称或第二人称。
- 保留反问、比喻、对照和情绪力度；不要额外添加煽情内容，也不要把原文观点擅自改写成另一套价值观。

### 视觉质量

- 观点表通常不超过四列，单元格只写摘要性信息。
- 小标题根据实际逻辑设置，相近主题合并；短文不强制分节，长文不必每两段一个标题。
- 自然段围绕一个完整意思组织，不一句一段，也不形成大段文字墙。
- 加粗只突出少量关键判断；引用块用于必要的原始对白和关键原句。
- 正文解释论点和案例，不机械重复表格。

### 四道审核

1. **任务一致性**：是否按用户指定的总结、讲解或只改格式执行？内容模式是否与材料匹配？
2. **信息覆盖**：独立论点、关键案例、对话、数字、比喻、转折、限制和个人补充是否保留？
3. **论证忠实**：案例是否支撑对应论点？有没有虚构因果、把推测写成事实、合并不同案例或补造细节？
4. **阅读质量**：是否避免第三方旁白、过度压缩、重复扩写、过多小标题、过宽表格和滥用加粗？

### 只改格式专用的保真核对

- 比较原文清除明确可确认复制噪声前后的非排版字符序列。
- 允许改变：空格、换行、段落间空行、Markdown 标题标记和确认属于复制残渣的格式符号。
- 不允许改变：具体词句、标点、数字、角色称呼、引号内原话、事件先后、故事结尾。
- 不擅自校对或润色；用户要求纯排版时，语义内容必须保持不变。
- 不增加总结表、观点分析、导读或个人评价。

### 可解释的不足，而不是假装完整

- “根据已提供的前两章整理，未含后续结局。”
- “目前只有视频转写，无法核对画面中的图表和动作。”
- “有关生理机制的判断保留为来源观点，尚未核验。”
- “来源没有交代这个案例的后续，因此不补写结果。”
