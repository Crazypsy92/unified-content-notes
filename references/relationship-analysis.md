# 情感观点分析型：案例论证与正文排版规范

本规范用于情感口播、亲密关系观点、恋爱认知、沟通冲突、择偶判断等材料。默认面向“观点分析型（案例论证增强版）”。

核心目标：**正文是一篇结构清楚的分析文章，不是故事会、轻小说或影视化改写。** 案例是论据，负责支撑观点；不是为了制造戏剧感而扩写的故事素材。

## 一、推荐成稿结构

观点明确、案例较多的材料，优先按以下顺序组织：

1. **原始标题**：原样保留。
2. **文章思想 / 核心主旨**：用一段简洁文字直接说明真正讨论的问题和主要判断。
3. **论点论据分析表**：对应主要论点、原始案例/论据、推理关系和结论。
4. **正文分析**：按论证顺序分节展开；每个关键案例都要在正文出现并得到分析。
5. **最终落点**：归纳文章真正要表达的关系认知。
6. **补充辨析 / 外部核验**：只在有必要时添加，明确区分原始内容与补充材料。

短文或纯故事不必机械套齐所有部分；由材料本身决定。

## 二、论点论据表怎么排

优先使用 4–5 列的紧凑表格，避免过宽、过密：

| 核心论点 | 原始案例 / 论据 | 推理关系 | 结论 / 落点 |
|---|---|---|---|

- 一行对应一个独立论点或一组紧密相关的论据。
- 案例较多时可在同一论点下列出多个案例，但必须能看出各自支撑什么。
- 不要把整段故事塞进表格；表格只做导航和逻辑映射。
- 原文没有提供的论据不能补写成“原文案例”。
- 表格里的案例概括，必须在正文中有相应展开。

## 三、正文排版：分析文章，不写成故事会

### 1. 使用清晰的分析层级

正文按“观点 / 关系问题 → 案例证据 → 行为与对话分析 → 推理结论”的顺序推进。

推荐形式：

### 一、回应的价值不在时长，而在于是否让对方感受到被重视

　　先直接说明这一节的判断，再解释它与整篇主旨的关系。不要用长篇气氛描写开场，也不要为了故事感把简单案例改写成戏剧场景。

#### 案例一｜忙碌时没有回应

　　用一至数段交代必要背景、双方行为、关键对话和结果。只保留与论点有关的细节。

　　**分析：** 说明双方关注点有什么不同，真正的矛盾在哪里，案例能支持哪一个论点。分析应紧贴证据，不替人物编造心理。

#### 案例二｜重要安排被工作打断

　　把事件经过和实际处理方式说清楚，不只写“对方很重视这段关系”。

　　**分析：** 解释补救行动传递了什么信号，以及它能说明什么、不能说明什么。

### 二、关系中的优先级，要看实际选择而不只听口头承诺

　　继续推进下一个论点，必要时用对照案例解释差异。

### 三、回到现实关系中的判断

　　整合前面的证据，说明适用条件、例外和边界。

### 2. 案例写法要具体，但保持分析语气

每个重要案例至少交代与论点有关的要素：

- 情境：发生了什么，人物之间是什么关系；
- 行为：各自做了什么，哪些选择是关键；
- 对话：有哪些原话能显示双方的关注点或冲突；
- 结果：对话或行为造成了什么可观察的结果；
- 分析：这些事实支持什么判断，推理中有哪些前提。

不要把案例改成小说式叙事：不添加天气、表情、动作、内心独白等原文没有的细节；不刻意制造悬念、反转或煽情结尾；不把每个案例写成一篇独立短篇故事。

案例较多时可以分别设置“案例一 / 案例二”，但每个案例后面都要有分析，不要只堆叙事。

## 四、情侣对话的视觉排版

对话是案例证据的一部分，可以适当做视觉区分，让读者快速看清双方说了什么。

推荐使用 Markdown 引用块：

~~~markdown
> **一方：** 你今天一直没有回复我。
>
> **另一方：** 我白天一直在忙，只有休息的时候才看了一下手机。
>
> **一方：** 我不是要求你一直聊天，只是希望你能告诉我一声。
~~~

对话后紧接分析：

　　**对话分析：** 双方争论的表面问题是回复频率，实际分歧是对“最低限度回应”的期待不同。这里不能直接推断任何一方不爱对方，需要结合后续行为和双方约定判断。

排版要求：

- 能确认说话人的，使用明确称呼；不能确认时使用“一方 / 另一方”，不要擅自补姓名。
- 一轮完整对话可以放在一个引用块中；较长对话按话题或轮次拆分。
- 关键原话可以加粗少量关键词，不要整段加粗。
- 对话原意和语气尽量保留；删减时不得改变立场。
- 不要把所有对话放进表格；表格用于归纳，引用块用于呈现原话。
- 对话后的分析必须说明它体现了什么，不要只做视觉装饰。

## 五、正文的视觉节奏

- 使用三级标题作为主要分析章节，四级标题只用于案例或必要子项。
- 标题写观点或问题，不要写成“故事一：他很忙”“一个令人心碎的夜晚”这类文学化标题。
- 每个自然段集中表达一个分析单元，通常 2–5 句；不要一句一段，也不要堆成大段墙。
- 段首两个全角空格；标题、表格、列表、引用块不缩进。
- 关键概念、对照关系和结论可适度加粗；不要整段加粗。
- 表格之后必须有正文，不能表格说完就结束。
- 不要每两段就插一个小标题；按逻辑层次分节，避免碎片化。
- 不使用 HTML、花哨卡片或大量装饰符号模拟视觉效果。

## 六、禁止的常见退化

| 不合格写法 | 应改为 |
|---|---|
| 把案例写成轻小说，增加环境、表情和心理独白 | 只保留原文事实，再分析行为与关系含义 |
| 只在表格中提到案例，正文不展开 | 在正文按案例逐个交代经过并解释 |
| 案例全部压成“双方缺乏沟通” | 写出具体分歧、对话和行为证据 |
| 正文只有条目，没有连贯论证 | 用完整段落解释论点之间的关系 |
| 每句话都单独成段 | 按一个完整意思组织自然段 |
| 频繁使用“作者认为 / 这篇文章讲了” | 直接陈述观点和分析 |
| 用外部电影/小说替代原文案例 | 原始案例优先，外部材料只作必要补充并标注来源 |

## 七、交付前专项检查

- [ ] 文章思想是否说清楚？
- [ ] 论点、论据和推理是否逐一对应？
- [ ] 每个核心案例是否在正文出现，而不只是表格里出现？
- [ ] 案例是否保持原始事实，没有小说化扩写？
- [ ] 情侣对话是否保留关键原话并清楚区分说话人？
- [ ] 对话之后是否解释了它与论点的关系？
- [ ] 正文是否像分析文章，而不是故事会或清单拼接？
- [ ] 标题层级、段落长度、缩进和加粗是否克制且清楚？
- [ ] 是否避免“作者认为 / 这篇文章讲了”等第三方介绍口吻？
