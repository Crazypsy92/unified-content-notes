## 观点分析型正文排版规范

本文件规定观点型长文、情感口播和多案例分析的正文组织方式。目标是写成**结构清楚的分析文章**，不是小说、轻小说、故事会或逐镜头叙事。

## 1. 适用范围与默认判断

适用于：
- 情感观点、亲密关系认知、吸引力、沟通、择偶、婚姻等观点型口播；
- 以一个中心观点串联多个生活案例、情侣对话或关系经历的文章；
- 用户明确要求“观点分析型”“论点论据”“案例分析”的材料。

如果材料本身是完整恋爱故事、小说剧情或影视剧情复盘，才采用叙事型写法。不要因为观点文章里有案例，就把整篇改成故事会。

## 2. 推荐的文章版式

### 标题与来源
- 使用原始标题：`## 原始标题`。
- 来源信息放在标题下的简短元数据中，例如：`> 来源：某 UP 主 / 视频标题`。
- 不要把 UP 主名称当成文章标题，也不要在正文里反复介绍内容来源。

### 文章思想
用一段自然中文直接说清楚核心问题和主旨。写观点本身，不写“这篇文章主要讲了……”或“作者想表达的是……”。

### 论点与论据分析表
观点型长文、有多个论点或案例时，默认提供一张分析表：

| 核心论点 | 原文案例 / 论据 | 推理关系 | 最终落点 |
|---|---|---|---|

要求：
- 一个核心论点对应它真正依赖的案例或证据。
- 多个案例分别列出，不要把不同人物的经历拼成一个笼统例子。
- “推理关系”说明案例如何支撑观点，不要只重复案例内容。
- 原文没有提供的证据留空或标明不足，不补造。
- 短文、纯故事和只改格式任务不强制使用分析表。

## 3. 正文采用分析文章结构，不采用故事会结构

正文按照观点之间的逻辑关系展开，常见顺序：
1. 提出需要解释的关系问题；
2. 说明核心观点及成立条件；
3. 分析第一个论点和对应案例；
4. 分析后续论点与案例，保留各自独立信息；
5. 对多个案例进行比较，说明共同点和差异；
6. 收束到文章主旨、现实启发或适用边界。

小标题应当是**分析判断或逻辑结论**，例如：
- `### 一、忙碌是现实限制，但及时回应仍然可以做到`
- `### 二、真正影响安全感的，是需求有没有被认真对待`
- `### 三、两个案例共同说明了关系中的优先级问题`

避免把观点分析型文章写成文学化、悬念化标题，例如“那个夜晚，她终于明白了……”“一场迟来的拥抱，改变了两个人”“藏在沉默背后的深情”，除非原始素材本身就是故事或用户明确要求文学化改写。

## 4. 案例要具体，但不能写成轻小说

案例的“展开”指还原论证所需的信息，不是文学化再创作。必须保留人物关系和必要背景、事件起因、关键行为、回应和结果、关键对话，以及案例与论点之间的逻辑联系。

不要添加原文没有的心理独白、神态、动作、环境、戏剧性细节、悬念或结局；不要把几个人的经历拼成一个“典型故事”。

案例较多时，每个重要案例都在正文中单独展开。推荐结构：

#### 案例一｜没有提前说明，等待容易变成不安

**情境与事实：** 简洁交代人物关系、发生了什么、关键行为和结果。

> **女方：** 你晚回来我可以理解，但为什么不提前告诉我？
>
> **男方：** 我以为很快就能结束，没想到拖到现在。

**分析：** 解释双方关注点、行为影响、冲突焦点，以及这个案例支撑哪一个论点。

**论证作用：** 仅在案例作用不明显时补充一句，说明它证明了什么、不能证明什么。

不要每个案例都机械重复四个标签。材料简单时合并成自然段；复杂案例才使用完整结构。案例越多，正文可以越长，但每一段都要服务于分析。

## 5. 情侣对话的视觉排版

原始情侣对话可使用带角色标签的 Markdown 引用块：

> **男方：** 我今天项目还没结束，可能要晚点回去。
>
> **女方：** 晚回来可以，但你为什么不提前告诉我？
>
> **男方：** 我以为很快就能结束，没想到拖到现在。

对话之后接分析，不把整篇观点文章写成剧本。长对话需要比较时，才使用“对话表现 / 可确认的信息 / 可能影响”小表格。

如果用户要求优化话术，可使用“原表达 / 调整表达”并明确标记。新拟的句子不能伪装成原始对话。分析对方意图时使用谨慎措辞，不把推测写成确定的心理诊断。

## 6. 段落、标题和视觉节奏

- 中文自然段首行缩进两个全角空格 `　　`，段间空一行。
- 正文以连续、自然的分析段落为主；不一句一段，也不堆成大段文字墙。
- 每段围绕一个分析任务：提出判断、解释原因、交代案例、分析对话或指出边界。
- 观点分析型正文通常使用 2—5 个主要逻辑小节，按实际论点数量调整，不为凑数拆标题。
- 案例标题简洁、事实化；不使用煽情标题。
- 表格用于总览和比较；正文负责解释，不把长篇论证塞进表格单元格。
- 不使用 HTML、彩色标签或装饰符号模拟视觉效果；使用标准 Markdown 标题、表格、引用和加粗即可。
- 最高标题级别为 `##`，正文主要小节为 `###`，案例子节必要时使用 `####`。

## 7. 输出前检查

- 主轴是论证还是叙事？有没有选错结构？
- 表格是否清楚呈现论点、证据、推理和结论？
- 每个重要案例是否在正文中真正写出来？
- 案例细节是否忠于来源，有没有被写成虚构故事？
- 小标题是否体现分析逻辑，而不是故事会式标题？
- 对话是否易读，角色是否清楚，原话和改写是否区分？
- 正文是否有连续、自然的分析段落，而不是碎片句或满屏列表？
- 是否避免第三方旁白口吻？
